# Отчёты о дефектах

Ниже оформлены наблюдения из задания. ОС, браузер, версия сборки и доказательства не предоставлены, поэтому их нужно добавить после воспроизведения, а не предполагать.

## BUG-01 — Возраст 18 лет отклоняется сообщением о минимальном возрасте

- **Окружение:** тестовая версия сервиса; ОС, браузер и версия сборки не указаны.
- **Предусловия:** открыта форма; остальные поля заполнены допустимыми данными; возраст — 18 лет.
- **Серьёзность:** высокая — блокируется регистрация пользователя, который соответствует обычной трактовке совершеннолетия.
- **Приоритет:** высокий — ошибка затрагивает основное бизнес-правило и граничное значение.

### Шаги воспроизведения
1. Открыть форму регистрации.
2. Заполнить имя, email и пароль допустимыми данными.
3. Указать возраст 18 лет.
4. Отправить форму.

### Фактический результат
Показывается сообщение «Регистрация доступна только с 18 лет».

### Ожидаемый результат
По обычной трактовке исходного требования пользователь, достигший 18 лет, должен иметь возможность зарегистрироваться. Точное правило необходимо подтвердить у заказчика.

### Дополнительные материалы
Наблюдение из задания. Скриншот и версия сборки не предоставлены; добавить после воспроизведения.

## BUG-02 — Двойное нажатие кнопки регистрации создаёт две учётные записи

- **Окружение:** тестовая версия сервиса; ОС, браузер и версия сборки не указаны.
- **Предусловия:** форма заполнена допустимыми данными; email ещё не зарегистрирован.
- **Серьёзность:** высокая — одна операция приводит к дублированию данных.
- **Приоритет:** высокий — целостность данных должна быть обеспечена до выпуска.

### Шаги воспроизведения
1. Открыть форму регистрации.
2. Заполнить все поля допустимыми значениями с новым email.
3. Дважды быстро нажать «Зарегистрироваться».
4. Проверить количество созданных записей для этого email.

### Фактический результат
Создаются две учётные записи.

### Ожидаемый результат
Одна операция регистрации должна создавать не более одной учётной записи. Повторные и параллельные запросы должны обрабатываться безопасно.

### Дополнительные материалы
Наблюдение из задания. После воспроизведения приложить скриншот и подтверждение количества записей, используя только тестовые данные.

## BUG-03 — Ошибка занятого email раскрывает полный объект пользователя

- **Окружение:** тестовая версия сервиса; ОС, браузер и версия сборки не указаны.
- **Предусловия:** в тестовой системе уже есть учётная запись с тестовым email; открыта форма регистрации.
- **Серьёзность:** высокая — техническое сообщение раскрывает сведения пользователя.
- **Приоритет:** высокий — возможная утечка данных требует исправления до выпуска.

### Шаги воспроизведения
1. Открыть форму регистрации.
2. Ввести уже зарегистрированный тестовый email.
3. Заполнить остальные поля допустимыми значениями.
4. Отправить форму.
5. Изучить сообщение об ошибке.

### Фактический результат
Система показывает полный объект пользователя в техническом сообщении об ошибке.

### Ожидаемый результат
Пользователь получает согласованное безопасное сообщение. Ответ не должен раскрывать полный объект пользователя, пароль, токены или внутренние технические детали. Точный текст следует согласовать.

### Дополнительные материалы
Наблюдение из задания. После воспроизведения приложить скриншот с замаскированными тестовыми данными и очищенный от секретов ответ API, если доступен. Реальные персональные данные не прикладывать.
