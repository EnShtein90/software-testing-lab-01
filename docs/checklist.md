# Чек-лист регистрации

**Важно:** исходные требования не определяют все форматы и границы. Неопределённые правила отмечены как требующие уточнения. Предлагаемые ограничения не считаются утверждёнными. Статус после выполнения: `Пройдено` / `Не пройдено` / `Требует уточнения`.

## 1. Имя пользователя
- [ ] **NAME-01 Позитивная.** Допустимое имя при корректных остальных полях принимается без ошибки валидации.
- [ ] **NAME-02 Обязательность.** Пустое имя блокирует отправку и вызывает сообщение об обязательности поля.
- [ ] **NAME-03 Негативная.** Имя только из пробелов отклоняется, если пробелы не разрешены правилами.
- [ ] **NAME-04 Границы — уточнить.** После согласования длины проверить значение на единицу ниже минимума, на минимуме, на максимуме и на единицу выше максимума.
- [ ] **NAME-05 Негативная — уточнить.** Запрещённые символы отклоняются с сообщением о допустимом формате.
- [ ] **NAME-06 Позитивная — уточнить.** Разрешённые национальные символы, дефис или апостроф принимаются, если они включены в согласованный набор.

## 2. Адрес электронной почты
- [ ] **EMAIL-01 Позитивная.** Согласованный корректный email принимается при корректных остальных полях.
- [ ] **EMAIL-02 Обязательность.** Пустой email блокирует отправку и вызывает сообщение об обязательности.
- [ ] **EMAIL-03 Негативная.** Адрес без `@` отклоняется с сообщением о неверном формате.
- [ ] **EMAIL-04 Негативная.** Адрес без доменной части отклоняется с сообщением о неверном формате.
- [ ] **EMAIL-05 Граница — уточнить.** После согласования максимальной длины адрес на пределе обрабатывается согласно правилу, а адрес длиннее предела отклоняется.
- [ ] **EMAIL-06 Уникальность.** Повторная регистрация с уже занятым email не создаёт вторую учётную запись.
- [ ] **EMAIL-07 Нормализация — уточнить.** Вариант email с другим регистром/пробелами обрабатывается по согласованным правилам и не создаёт запрещённый дубликат.
- [ ] **EMAIL-08 Безопасность.** Ошибка уникальности не содержит полного объекта пользователя, пароля, токенов или технического стека.

## 3. Пароль
- [ ] **PASS-01 Позитивная — уточнить.** Пароль, отвечающий согласованной политике, принимается.
- [ ] **PASS-02 Обязательность.** Пустой пароль блокирует отправку и вызывает сообщение об обязательности.
- [ ] **PASS-03 Негативная.** Пароль, нарушающий согласованное минимальное требование, отклоняется с пояснением.
- [ ] **PASS-04 Границы — уточнить.** Проверить минимальную/максимальную длину и значения за их пределами после согласования.
- [ ] **PASS-05 Безопасность.** Пароль не отображается открытым текстом в техническом ответе об ошибке.
- [ ] **PASS-06 Безопасность.** Пароль не записывается в тестовые журналы в открытом виде.
- [ ] **PASS-07 Позитивная — уточнить.** Пробелы и специальные символы обрабатываются по утверждённой парольной политике.

## 4. Возраст
- [ ] **AGE-01 Позитивная/граница.** Возраст 18 лет допускает регистрацию при корректных остальных данных.
- [ ] **AGE-02 Негативная/граница.** Возраст 17 лет отклоняется с сообщением об ограничении.
- [ ] **AGE-03 Позитивная.** Возраст старше 18 лет допускается при корректных остальных данных.
- [ ] **AGE-04 Обязательность.** Пустой возраст отклоняется с сообщением, если поле подтверждено как обязательное.
- [ ] **AGE-05 Негативная.** Буквенное значение отклоняется с сообщением о допустимом формате.
- [ ] **AGE-06 Негативная.** Отрицательный возраст отклоняется, учётная запись не создаётся.
- [ ] **AGE-07 Граница — уточнить.** Дробное значение обрабатывается согласно согласованному формату.
- [ ] **AGE-08 Безопасность.** Прямой API-запрос с возрастом 17 лет отклоняется сервером.

## 5. Успешная регистрация
- [ ] **REG-01 Позитивная.** Корректное заполнение формы создаёт ровно одну учётную запись.
- [ ] **REG-02 Позитивная.** После подтверждённого успеха отображается согласованное сообщение об успешной регистрации.
- [ ] **REG-03 Позитивная.** При успешном ответе сообщение об ошибке для той же операции не показывается.
- [ ] **REG-04 Интеграционная.** Сохранённая запись содержит ожидаемые значения полей без повреждения данных.
- [ ] **REG-05 Негативная.** При отказе сервера частичная учётная запись не остаётся в хранилище.
- [ ] **REG-06 Безопасность.** Пароль не показывается в подтверждении и не возвращается клиенту открытым текстом.

## 6. Обработка ошибок
- [ ] **ERR-01 Негативная.** Пропуск обязательного поля вызывает сообщение с указанием поля.
- [ ] **ERR-02 Негативная.** Некорректный email вызывает понятное сообщение без технического стека.
- [ ] **ERR-03 Негативная.** При недоступности сервера отображается понятное сообщение о невозможности завершить операцию.
- [ ] **ERR-04 Безопасность.** Ошибка не раскрывает пароль, токены, внутренние идентификаторы или полный объект пользователя.
- [ ] **ERR-05 Ручная.** Пользователь без технических знаний понимает сообщение и следующий шаг.
- [ ] **ERR-06 Восстановление.** После исправления ошибочного поля форму можно повторно отправить согласно согласованному поведению.

## 7. Повторная отправка формы
- [ ] **RETRY-01 Интеграционная.** Двойное быстрое нажатие не создаёт две учётные записи.
- [ ] **RETRY-02 Интеграционная.** Повтор запроса после задержки сети не создаёт дубликат.
- [ ] **RETRY-03 Позитивная.** Если первый запрос не был принят сервером, безопасный повтор позволяет завершить регистрацию.
- [ ] **RETRY-04 Негативная.** Повтор регистрации уже занятого email не создаёт новую запись и показывает согласованное сообщение.
- [ ] **RETRY-05 Нефункциональная.** При согласованной нагрузке повторные запросы не нарушают целостность данных.

## Классификация 15 проверок

Уровни: модульный — отдельная функция/компонент; интеграционный — взаимодействие компонентов; системный — система целиком; приёмочный — соответствие согласованным ожиданиям пользователя/заказчика. Автоматизация указана как предпочтительный способ, а не как утверждение, что тест уже автоматизирован.

| ID проверки | Уровень (предпочтительный) | Вид | Характер | Способ | Обоснование |
|---|---|---|---|---|---|
| NAME-02 | Модульный | Функциональный | Негативный | Автоматизированный | Проверка обязательности отдельного поля легко повторяется автоматически |
| NAME-04 | Модульный | Функциональный | Негативный | Автоматизированный | Граничные значения длины удобно проверять набором тестовых данных после согласования |
| EMAIL-01 | Системный | Функциональный | Позитивный | Автоматизированный | Проверяет работу формы от ввода до успешного результата |
| EMAIL-03 | Модульный | Функциональный | Негативный | Автоматизированный | Проверяет правило валидации формата адреса |
| EMAIL-06 | Интеграционный | Функциональный | Негативный | Автоматизированный | Важно взаимодействие проверки уникальности и хранилища |
| EMAIL-08 | Системный | Нефункциональный (безопасность) | Негативный | Ручной и автоматизированный | Проверяет отсутствие утечки в реальном ответе; автоматизируемые проверки можно дополнить ручным анализом |
| PASS-05 | Системный | Нефункциональный (безопасность) | Негативный | Автоматизированный | Ответ API можно автоматически проверять на наличие секретов |
| AGE-01 | Модульный | Функциональный | Позитивный | Автоматизированный | Изолированно проверяет правило допустимости возраста на границе |
| AGE-02 | Модульный | Функциональный | Негативный | Автоматизированный | Значение 17 должно быть отклонено правилом проверки возраста |
| AGE-08 | Интеграционный | Функциональный / безопасность | Негативный | Автоматизированный | Подтверждает, что сервер применяет ограничение независимо от интерфейса |
| REG-01 | Системный | Функциональный | Позитивный | Автоматизированный | Проверяет полный сценарий создания ровно одной записи |
| REG-04 | Интеграционный | Функциональный | Позитивный | Автоматизированный | Проверяет согласованность данных между приложением и хранилищем |
| ERR-05 | Приёмочный | Нефункциональный (удобство использования) | Негативный | Ручной | Понятность сообщения требует оценки человеком по согласованным критериям |
| RETRY-01 | Интеграционный | Функциональный | Негативный | Автоматизированный | Проверяет совместную работу интерфейса, запросов и сохранения данных |
| RETRY-05 | Системный | Нефункциональный (производительность/целостность) | Негативный | Автоматизированный | Нагрузочный сценарий требует повторяемого запуска и сбора метрик |

## Примечание
Классификация может иметь альтернативы. Например, возраст можно проверить модульно для логики и системно для всей формы. Выбран предпочтительный уровень, на котором проверка быстрее и точнее выявляет соответствующий класс дефектов.
